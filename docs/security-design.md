# VaultSec 安全设计文档

> 版本：v1.0.0
> 适用范围：Android / Windows / Linux（Capacitor 跨端）
> 文档用途：安全架构说明、应用商店隐私合规申报依据

---

## 1. 安全目标

- **零泄露设计**：主密码与全部密码条目数据在设备外不可还原、不可读取。
- **本地优先**：所有敏感数据仅存于设备本地（WebView IndexedDB 沙箱），不依赖任何云端服务。
- **离线可破解性**：即使攻击者完整获得设备存储文件，在未知主密码的情况下无法解密任何条目。

## 2. 加密架构总览（信封加密 Envelope Encryption）

采用业界密码管理器标准的两层密钥信封加密方案（1Password / Bitwarden 同架构）：

```
主密码 Master Password（用户输入，永不落盘、永不上传）
    │
    │  PBKDF2-HMAC-SHA256（600,000 次迭代 + 16 字节随机盐）
    ▼
KEK 密钥加密密钥（Key Encryption Key，仅用于包装主密钥）
    │
    │  AES-256-GCM 包装（wrap）／解包（unwrap）
    ▼
vaultKey 主密钥（随机生成 256 位，仅存活于内存）
    │
    │  AES-256-GCM（每条目独立随机 12 字节 IV）
    ▼
密文落盘（IndexedDB）
```

### 2.1 各密钥角色

| 密钥 | 长度 | 生命周期 | 存储位置 | 用途 |
|---|---|---|---|---|
| 主密码 Master Password | 用户自定 | 输入即用 | **不落盘** | 派生 KEK 的唯一输入 |
| KEK | 256 位 | 派生后即用 | 内存，用后丢弃 | 包装/解包 vaultKey |
| vaultKey 主密钥 | 256 位 | 解锁期间 | **仅内存**，锁屏即清空 | 加解密全部密码条目 |

## 3. 数据落盘明细

持久化层为 WebView IndexedDB（数据库名 `vault_secure`，Android 端位于应用沙箱内）。共两个键：

### 3.1 `meta`（保险库元数据）

| 字段 | 明文/密文 | 说明 |
|---|---|---|
| `version` | 明文 | 结构版本号（当前 1） |
| `salt` | 明文 | 16 字节随机盐（base64），用于派生 KEK，无敏感性 |
| `iterations` | 明文 | PBKDF2 迭代次数（600,000），无敏感性 |
| `wrap` | **密文** | 被 KEK 加密的 vaultKey（AES-256-GCM） |
| `verifyToken` | **密文** | 主密钥自加密令牌，用于指纹快捷解锁时的密钥一致性校验 |
| `settings` | 明文 | 应用设置（双因子开关、自动锁定、失败销毁阈值、剪贴板自动清空），无敏感性 |
| `biometrics` | 部分密文 | 指纹/WebAuthn 凭据信息（凭据材料加密存储） |
| `failedAttempts` | 明文 | 连续失败次数，用于失败销毁策略 |

### 3.2 `entries`（密码条目集合）

每条记录结构：`{ id, iv, ct, updatedAt }`

| 字段 | 明文/密文 | 说明 |
|---|---|---|
| `id` | 明文 | 随机生成的条目 ID（无敏感性） |
| `updatedAt` | 明文 | 更新时间戳 |
| `iv` | 明文 | 本条目的 12 字节随机初始化向量（base64），GCM 标准允许公开 |
| `ct` | **密文** | **整条记录**（name / username / password / url / notes / category 序列化为 JSON 后）的 AES-256-GCM 密文 |

> 关键点：条目内的所有字段（含用户名、密码、URL、备注、分类）作为一个整体加密。攻击者即使拿到密文，也无法获知记录包含几个字段、分别是什么。

## 4. 加密算法与参数

| 项 | 参数 | 依据 |
|---|---|---|
| 对称加密 | AES-256-GCM（认证加密） | 同时保证机密性 + 完整性（防篡改） |
| 密钥派生 | PBKDF2-HMAC-SHA256，600,000 次迭代 | OWASP Password Storage Cheat Sheet 推荐 ≥ 600,000 |
| 盐 | 每次创建保险库随机 16 字节（`crypto.getRandomValues`） | 防彩虹表 / 相同密码产生相同 KEK |
| 初始化向量 IV | 每条目每次保存独立随机 12 字节 | 防相同内容产生相同密文（IV 重用攻击防御） |
| 主密钥 | `crypto.getRandomValues` 生成的 256 位随机值 | 密码学安全随机源 |
| 随机 ID | 16 字节随机数 base64 | 防条目 ID 枚举 |

### 4.1 防篡改与密码校验

- **GCM 认证标签**：所有密文（wrap、verifyToken、条目 ct）均带认证标签。密文被篡改或主密码错误时，解包必然失败并抛出异常。
- **密码正确性判定**：依赖「解包 wrap 时 GCM 认证通过与否」来判断主密码是否正确，**不存储任何密码哈希**，主密码不以任何形式落盘。

## 5. 核心流程

### 5.1 创建保险库（首次使用）

1. 生成 16 字节随机盐
2. 主密码 + 盐 → PBKDF2 派生 KEK
3. 随机生成 256 位 vaultKey
4. KEK 加密 vaultKey 得 `wrap`（AES-256-GCM）
5. 主密钥自加密生成 `verifyToken`
6. 元数据 + 空条目表落盘
7. vaultKey 载入内存，进入解锁态

### 5.2 解锁（主密码）

1. 读取 `meta.salt`，主密码派生 KEK
2. 解包 `wrap` 得 vaultKey（失败 = 密码错误）
3. （可选）双因子：若启用且已录入指纹，需生物识别验证通过
4. 用 vaultKey 逐条解密 `entries` 到内存
5. 清零失败计数

### 5.3 解锁（指纹快捷解锁）

1. 通过 WebAuthn PRF / 原生生物识别取回 vaultKey
2. 用 `verifyToken` 二次校验取回密钥与真实主密钥一致（防凭据替换）
3. 校验通过后进入解锁流程

### 5.4 修改主密码

- 仅需「换信封」：旧 KEK 解出 vaultKey → 新盐派生新 KEK → 重新包装。
- **无需重新加密任何条目**，数据层密文保持不变。

### 5.5 锁定与销毁

- **手动/自动锁定**：清空内存中的 vaultKey、密钥对象、明文条目。
- **失败销毁**：连续错误达到阈值（默认 10 次，可配置或关闭）后，清空整个数据库，等效于彻底销毁所有密文与密钥材料。

## 6. 剪贴板安全

- 复制密码后按设置（默认 30 秒）自动清空系统剪贴板。
- 减少密码残留在剪贴板被其他应用读取的窗口期。

## 7. 平台与通道安全

| 层面 | 措施 |
|---|---|
| 应用沙箱 | Android WebView IndexedDB 位于应用私有数据目录，受系统应用隔离保护 |
| 系统安全 | Android 全盘加密（FBE）+ 锁屏保护 |
| 网络 | 本应用不传输任何保险库数据；如未来接入云同步，须采用端到端加密 |
| 生物识别 | 通过系统级安全硬件（TEE/SE）与 WebAuthn 凭据保护密钥材料 |

## 8. 已知边界与建议（诚实披露）

1. **逆向友好度**：release 构建当前未开启 `minifyEnabled`（JS 代码未被混淆）。加密强度不依赖代码保密（Kerckhoffs 原则），但若需提高门槛，可开启代码混淆。
2. **内存攻击面**：解锁期间 vaultKey 与明文条目存在于 WebView 进程内存，无法避免；依赖锁定策略（自动锁定、失败销毁）缩短暴露窗口。
3. **主密码强度**：整体安全下限由主密码熵决定。建议应用内强密码校验 + 提示用户使用 ≥ 12 位混合密码。
4. **云同步缺失**：当前为纯本地存储，无账号体系；换机需手动迁移，同步方案落地前不引入任何云端数据。

## 9. 合规申报要点（应用商店 Data Safety）

| 申报项 | 结论 |
|---|---|
| 收集的个人信息 | **不收集**（无账号、无遥测、无广告 SDK） |
| 收集的用户数据 | 仅本地密文，不离开设备 |
| 数据加密 | AES-256-GCM 加密存储，密钥派生 PBKDF2-600,000 |
| 数据删除 | 支持一键销毁（失败阈值自动销毁 / 手动清空） |
| 生物识别 | 仅用于本地解锁，凭据存于系统安全硬件 |
| 第三方 SDK | 无广告/统计/埋点 SDK（仅 Capacitor 生态插件） |

## 10. 威胁模型小结

| 攻击场景 | 防线 |
|---|---|
| 存储文件被拷贝（设备丢失/备份提取） | 全量 AES-256-GCM 密文 + PBKDF2 高成本离线爆破 |
| 主密码猜测（在线/离线暴力） | 600,000 次 PBKDF2 显著拉高单次猜测成本 + 失败次数限制/销毁 |
| 密文篡改 | GCM 认证标签校验，篡改即解密失败 |
| 相同明文指纹 | 独立随机 IV，同内容不同密文 |
| 凭据替换（指纹通道） | verifyToken 密钥一致性校验 |
| 明文残留（剪贴板） | 自动清空剪贴板 |
